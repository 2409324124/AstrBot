# AMD EPYC 7001 Naples 与 7002 Rome 完整型号目录

EPYC 7001 和 7002 都使用 SP3，但代际差异很大。7001 把核心、内存控制器和 I/O 分布在四个 Zeppelin die 上；7002 改为 Zen 2 CCD 加中心 I/O die，提升到 64 核、DDR4-3200 和 PCIe 4.0。二手平台可能通过 BIOS 升级兼容两代 CPU，但是否支持全部 7002 功能必须以服务器厂商的机型与 BIOS 支持表为准。

7001 的每个 die 都带本地内存控制器，因此 NPS、内存插条分布和线程绑定会显著影响延迟与带宽。即使机器能识别全部容量，未按八通道对称插 DIMM 也可能大幅降低内存密集型工作负载的性能。

## 7001 与 7002 的平台差异

| 项目 | EPYC 7001 Naples | EPYC 7002 Rome |
|---|---|---|
| CPU 核心 | Zen，14nm | Zen 2，7nm CCD |
| 最大核心数 | 32 | 64 |
| I/O 组织 | 每个 die 带内存/I/O | 中心 I/O die |
| 内存 | 8 通道 DDR4，常见最高 2666MT/s | 8 通道 DDR4-3200 |
| PCIe | 128 lanes PCIe 3.0 | 128 lanes PCIe 4.0 |
| L3 上限 | 64MB | 256MB |
| 单路后缀 | P | P |

从 7001 升级到 7002 时，CPU 插槽相同并不等于无条件兼容。必须核对 OEM 的 CPU support matrix、BIOS/AGESA、散热器功耗等级、DIMM 速度和 PCIe 4.0 走线认证。老主板即使能启动 7002，也可能只能以 PCIe 3.0 工作或缺少新 CPU 的完整功能。

## 用于本地 AI 的判断

EPYC 7002 的 8 通道 DDR4-3200 和中心 I/O die 通常比 7001 更适合 CPU offload、向量数据库、文档预处理和多 GPU I/O。可是单线程 tokenizer、压缩和请求调度仍可能受较低频率影响；高核心数不能代替对真实流水线的 profiling。

P 后缀对单机 GPU 服务器往往更划算，因为单路仍保留完整内存通道和 PCIe lanes。若工作负载确实需要双路，应把 GPU/NIC/NVMe 绑定到本地 NUMA node，避免跨 socket Infinity Fabric 流量。
